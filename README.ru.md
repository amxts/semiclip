# Semiclip

*Кто сквозь кого проходит — правилом над двумя игроками*

Семиклип позволяет игрокам проходить сквозь друг друга. amxts делает это на сервере сам, [парами игроков](https://amxts.github.io/ru/docs/game/players#проход-сквозь-друг-друга) (`player.walksThrough`); этот модуль даёт плагину сказать, кто сквозь кого проходит, правилом над двумя игроками, `(player, target) => boolean`, и держит пары в курсе.

## Возможности

- **Правило, а не пары вручную.** Одна функция говорит, проходит ли один игрок сквозь другого; модуль рассчитывает каждую пару.
- **Держится в курсе сам.** Появление, смерть, смена команды, вход игрока и изменение любого поля, которое плагины добавили в `Player`, заново рассчитывают пары — только пары того игрока, с которым это случилось.
- **Больше ничего на сервере.** Модуль AMX Mod X не нужен: пары — собственные у amxts.
- **Один экземпляр на сервер.** Все плагины, которые им пользуются, задают одно и то же правило.

## Установка

Проекту нужен `@amxts/core` 0.3.3 или новее.

```bash
npx amxts module add resemiclip
```

Команда ставит пакет и добавляет его в `amxts.config.ts` проекта:

```ts
export default defineConfig({
	modules: ["@amxts/resemiclip"],
});
```

## Использование

Плагин пользуется модулем как `semiclip`, без строки импорта: сборка добавляет импорт в те плагины, которые им пользуются, и собирает модуль, только когда им пользуется хоть один.

Союзники проходят сквозь друг друга:

```ts
semiclip.rule = (player, target) => player.team == target.team;
```

Больше ничего не нужно: модуль рассчитывает каждую пару и заново рассчитывает пары игрока, когда тот появляется, умирает, меняет команду или входит. `semiclip.rule = null` снова делает всех твёрдыми, и так же — остановка плагина, который задал правило (его выгрузили или перезагрузили), пока правило не задано снова.

### Правило, которое меняется в игре

`spawnProtected` ниже — собственное [поле плагина в `Player`](https://amxts.github.io/ru/docs/game/players#общие-поля-игрока), объявленное через `declare module`: сначала оно `false`, его читают и пишут все плагины сервера, а когда игрок уходит, оно сбрасывается. Только что появившийся игрок 3 секунды проходит сквозь всех живых, а союзники — сквозь друг друга:

```ts
declare module "@amxts/core" {
	interface Player {
		spawnProtected: boolean;
	}
}

semiclip.rule = (player, target) =>
	player.isAlive && target.isAlive && (player.spawnProtected || player.team == target.team);

game.addEventListener("spawn", ({ player }) => {
	player.spawnProtected = true;                        // 3 секунды проходит сквозь всех
	setTimeout(() => (player.spawnProtected = false), 3000);
});
```

Модуль сам заново рассчитывает пары, когда поле меняется, — при появлении и когда таймер его снимает, — без вызова `update()`.

### Когда пары рассчитываются

| Когда | Какие пары |
| --- | --- |
| задано `rule` | все пары |
| игрок вошёл в игру | его |
| игрок появился, умер или сменил команду | его |
| у игрока изменилось поле, которое плагины добавили в `Player`, — любым плагином или Pawn | его |
| игрок ушёл | его пары уходят вместе с ним |
| `semiclip.update(player)` | пары `player` |
| `semiclip.update()` | все пары |

`update()` — для того, что читает правило, но чего модуль не слышит: режим раунда в переменной, собственная запись плагина об игроке:

```ts
let everyone = false;

semiclip.rule = (player, target) => everyone || player.team == target.team;

server.addCommand("/party", () => {
	everyone = !everyone;
	semiclip.update();
});
```

### Пару пропускает любая сторона

`rule(player, target)` говорит, проходит ли `player` сквозь `target`, но пара одна: двое либо проходят сквозь друг друга, либо нет. Пара проходит, когда правило разрешает хотя бы одному — `rule(a, b) || rule(b, a)`. Правило, которое говорит да для защищённого игрока, пропускает его сквозь всех и всех сквозь него, без `|| target.spawnProtected`.

### Кто сквозь кого проходит сейчас

Пары — это пары ядра: `player.walksThrough.has(other)` говорит, проходят ли двое сквозь друг друга, а список такой:

```ts
const partners = server.players.filter(other => player.walksThrough.has(other));
```

### Как выглядит партнёр

Игрок, сквозь которого проходишь, вблизи может быть полупрозрачным или не рисоваться совсем, чтобы не закрывать обзор. Это `server.walkThroughLook` ядра — для всех игроков, по умолчанию выключено:

```ts
server.walkThroughLook.fadeDistance = 250;  // ближе 250 юнитов партнёр полупрозрачный
server.walkThroughLook.opacity = 0.4;       // вплотную непрозрачен на 40%, целиком — на 250
server.walkThroughLook.hideDistance = 32;   // ближе 32 юнитов его не видно совсем
```

> [!WARNING]
> На сервере без ReGameDLL партнёр, который стоит между игроком и флешкой, закрывает её свет, как любой другой. Проход сквозь, вид и гранаты работают на любом сервере.

### Одно правило

Правило на сервере одно. Плагин, который задаёт его поверх правила другого плагина, заменяет его, а консоль предупреждает: действует последнее заданное. Плагины, у каждого из которых есть своё слово, пишут его в поля (`player.spawnProtected`), которые читает одно правило.

## API

| Член | Что это |
| --- | --- |
| `semiclip.rule` | `(player, target) => boolean` — проходит ли `player` сквозь `target`; пара проходит, когда разрешает любая сторона. Присваивание рассчитывает каждую пару; `null` снова делает всех твёрдыми. |
| `semiclip.update(player?)` | Заново рассчитывает пары `player` или всех, после того как изменилось то, что читает правило и чего модуль не слышит. |
